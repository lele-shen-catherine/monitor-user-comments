# 抖音用户评论监测页面结构

## 页面头部

- 标题、关键词、执行时间、时区和数据来源。
- 只显示抖音，不提供平台切换。
- 提供“长周期”和“近7天”两个时间视图；近7天属于长周期子集。
- 页面顶部提供关键词搜索框、“快速监测”和“深度监测”操作。快速监测默认使用 20 条高赞帖子 × 每帖最多 50 条评论；深度监测必须由用户主动选择。静态文件模式不得假装已经启动任务。

## 每个时间视图

1. 指标卡：匹配帖子、有效评论、正面占比、负面占比。
2. 正面与负面高频主题 Top 10。
3. 可复刻玩梗：从高赞帖子及其高赞评论中识别，展示表达模板、复刻公式、玩法、帖子/评论来源、互动热度和脱敏代表内容。
4. 用户关心点：问题、证据规模、原因假设、期望改进、负责团队、验证指标和脱敏原文。
5. 高互动帖子：标题、链接、点赞、评论和结论强度。
6. 口径与限制：数据覆盖、抽样偏差、小样本、玩梗误判风险和人工复核状态。

## 视觉要求

- 复用既有前端的米白页面、青绿色主色、白色圆角卡片、左侧导航和红色风险提示。
- 页面响应式布局，手机和桌面均可阅读。
- 生成单个自包含 HTML 文件，不依赖外部 CSS、JavaScript、字体或服务器。
- 页面内容必须由当次数据注入，不保留演示数字、演示评论或无效链接。

## 配套文件

- HTML 是每次运行的必需交付。
- 人工复核 CSV 用于修正情绪和主题标签。
- Markdown 是可选追溯附件，不能替代 HTML 页面。
